## 第一部分：UI设计方案（V2.1评审优化版）

### 一、用户研究分析

#### 1.1 用户画像

##### 孩子用户（3-7岁儿童）

为更精准地指导设计，将孩子用户按认知与行为特征细分为两组：

**3-4岁组（启蒙期）**

| 特征    | 描述                     |
| ----- | ---------------------- |
| 认知水平  | 前运算阶段早期，完全具象思维，符号理解有限  |
| 注意力时长 | 3-5分钟                  |
| 精细动作  | 触控热区需求 ≥ 60dp，不支持复杂手势  |
| 喜好    | 大面积动画形象、简单音效、重复性互动     |
| 需求    | 安全感、即时陪伴、感官安抚          |
| 操作方式  | 多由家长辅助操作，或由家长启动后交由孩子使用 |

**5-7岁组（成长期）**

| 特征    | 描述                       |
| ----- | ------------------------ |
| 认知水平  | 前运算阶段后期，初步逻辑思维，能理解简单因果   |
| 注意力时长 | 5-10分钟                   |
| 精细动作  | 触控热区需求 ≥ 48dp，可完成拖拽、选择操作 |
| 喜好    | 故事性强的内容、成就收集、角色互动        |
| 需求    | 安全感、自主探索、成就感             |
| 操作方式  | 可独立完成基础操作，需要清晰的视觉引导      |

##### 家长用户

**主要用户：28-35岁宝妈**

| 特征     | 描述                                               |
| ------ | ------------------------------------------------ |
| 决策角色   | 家庭购买决策者，产品主要使用者                                  |
| 关注点    | 专业可信度、效果可见、价格合理、操作省心                             |
| 行为特征   | 每日使用1-2次，单次5-15分钟；偏好晚间使用                         |
| 痛点     | 孩子怕黑/夜醒/入睡困难；试过讲故事但孩子越听越兴奋；不知道孩子夜醒几次算正常；缺乏科学应对方法 |
| 需求     | 科学方法、省心便捷、效果跟踪、专业背书                              |
| 信息获取渠道 | 小红书、母婴社群、儿科医生推荐、朋友口碑                             |
| 竞品使用情况 | 部分使用过凯叔讲故事、小睡眠等，迁移成本中等                           |

**次要用户：28-40岁宝爸**

| 特征   | 描述                    |
| ---- | --------------------- |
| 决策角色 | 参与使用者，偶尔独立陪护          |
| 关注点  | 操作简单、效果直接             |
| 行为特征 | 使用频率低于宝妈，偏好简洁界面       |
| 设计影响 | 家长端需兼顾简洁性，避免过度女性化视觉风格 |

#### 1.2 用户场景分析

**场景一：睡前常规场景（高频）**

- **时间：** 每晚20:30-21:30
- **流程：** 家长打开APP → 选择故事 → 交给孩子听 → 孩子在故事中入睡 → 定时关闭
- **情绪状态：** 家长疲惫但耐心，孩子兴奋需要平静
- **关键需求：** 快速找到合适内容、定时自动关闭、屏幕自动调暗

**场景二：日常查看场景（中频）**

- **时间：** 白天碎片时间
- **流程：** 家长查看睡眠数据 → 阅读育儿知识 → 学习沟通话术
- **情绪状态：** 关注但不紧急
- **关键需求：** 数据直观、知识可信、操作便捷

**场景三：噩梦应急场景（低频但关键）**

- **时间：** 深夜，孩子突然哭醒
- **流程：** 家长安抚 → 打开APP → 快速进入安抚模式 → 孩子重新平静入睡
- **情绪状态：** 家长焦虑、孩子恐惧
- **关键需求：** 快速直达（≤2步操作）、安抚内容即时可用、屏幕低亮度、柔和音效

**场景四：成长记录场景（低频）**

- **时间：** 周末或月末
- **流程：** 家长查看周报/月报 → 分享给家人或社交平台
- **关键需求：** 可视化成长数据、便捷分享

### 二、信息架构规划

#### 2.1 应用结构

应用架构总览：

- **孩子端（独立导航体系）**
  - 首页（守护IP + 故事入口）→ 守护IP故事 / 故事播放
  - 课程（分级脱敏课程）→ 课程学习
  - 呼吸（呼吸放松引导）→ 呼吸练习
  - 打卡（睡眠打卡）
  - 安抚模式（噩梦应急·快捷入口）
- **家长端（独立导航体系）**
  - 首页（数据概览 + 智能推荐）→ 睡眠数据报告 / 成长档案
  - 知识（科学育儿知识）→ 文章详情 / 话术库
  - 服务（专家咨询 + 会员）→ 专家咨询 / 会员中心
  - 我的（个人中心 + 设置）→ 账号管理 / 孩子档案 / 通知设置 / 通用设置
- **系统级模块**
  - 注册/登录
  - 新手引导
  - 推送通知策略
  - 暗色模式切换

**双端切换与儿童锁机制（V2.1新增核心设计）：**

- **孩子端→家长端：** 不存在任何可直接进入家长端的常规入口。唯一方式是通过家长端“我的”页面中的“陪宝宝进入晚安世界”进入孩子端。若需从孩子端返回家长端，必须通过**成人验证（儿童锁）**，如随机两位数加法、图形旋转验证等，确保成人操作。
- **家长端→孩子端：** 从“我的”页面点击进入，无需再次验证（因已验证过成人身份），但退回到家长端仍需重新通过儿童锁。
- **应急穿透：** 家长端首页保留“一键安抚”按钮，可直接触发孩子端安抚模式，紧急场景下0步直达，无需切换至孩子端。

#### 2.3 导航设计

**孩子端导航：**

- 采用底部Tab导航，共4个Tab：故事、课程、呼吸、打卡
- Tab图标采用大尺寸（32dp），配合简短文字标签
- 安抚模式通过首页长按守护IP或摇晃手机触发（快捷入口，不在Tab中）
- 3-4岁组：图标为主，文字为辅；5-7岁组：图标+文字并重

**家长端导航：**

- 采用底部Tab导航，共4个Tab：首页、知识、服务、我的
- 页面内部采用顶部返回导航

#### 2.4 异常状态设计

| 状态        | 呈现方式           | 说明                                                               |
| --------- | -------------- | ---------------------------------------------------------------- |
| 首次使用（无数据） | 引导卡片 + 示范数据    | 数据报告页展示"开始使用后这里会显示宝宝的睡眠数据"，配以守护IP引导动画                            |
| 列表为空      | 空状态插画 + 操作引导   | 如"还没有故事哦，让月亮精灵给你讲第一个吧"                                           |
| 网络断开      | 离线提示 + 缓存内容可用  | 已下载的故事和课程可离线使用，未缓存内容显示离线提示                                       |
| 加载中       | 骨架屏 + 主题加载动画   | 使用守护IP呼吸动画作为加载指示器（V2.1优化：加载时展示月亮精灵侧卧蜷缩的呼吸动画，代替传统灰色方块，将等待转化为安心体验） |
| 操作失败      | Toast提示 + 重试按钮 | 友好的错误提示，避免技术术语                                                   |
| 服务器异常     | 全页提示 + 离线模式入口  | 提供已缓存内容的访问                                                       |

### 三、交互流程设计

#### 3.1 孩子端核心流程

**故事播放流程**

流程路径：进入首页 → 选择守护IP → 浏览故事列表 → 点击播放 → 播放控制

分支路径：

- 返回 → 回到首页
- IP互动对话 → 点击IP触发对话气泡
- 暂停/切歌 → 播放控制操作
- 继续播放 → 播放中互动（点击IP触发对话）
- 播放完成 → 获得勋章 → 勋章展示动画 → 查看勋章/跳过
- 自动进入助眠模式（白噪音+屏幕渐暗）→ 定时关闭 → 屏幕熄灭

**中断保护设计（V2.1新增）：**
当孩子误触底部Tab进入课程/呼吸等页面时，故事播放不停止，并在新页面顶部显示悬浮返回条："故事还在播哦～"，附带月亮精灵微缩头像和"返回故事"按钮。该悬浮条5秒后自动收起为一侧小圆点，点击仍可返回。

后台播放规则：切换到其他页面时，底部显示迷你播放器
中断处理规则：来电/通知后自动恢复播放，音量渐入

**迷你播放器情感化设计（V2.1新增）：**
底部迷你播放器周围带有微弱的呼吸光晕（暖橙色），光晕缓慢明灭。当故事暂停时，光晕变为柔和的跳动光点，引导孩子返回播放页。

**脱敏课程流程（含断点续学）**

进入课程页 → 选择等级 → 查看进度

分支路径：

- 继续上次课程（断点续学提示）→ 课程学习（3-5分钟/单元）
- 开始新课程（学习目标展示）→ 课程学习（3-5分钟/单元）

课程学习后：

- 完成当前单元（单元奖励）→ 解锁下一单元
- 中途退出（自动保存进度）→ 下次启动时提示续学

**噩梦安抚流程（应急场景）**

触发方式：

- 孩子端：长按守护IP 2秒 / 摇晃手机
- 家长端：首页"一键安抚"按钮 / 锁屏小组件
- 语音唤醒：支持"小月亮，我害怕"语音触发（如集成语音SDK）

流程：触发安抚模式 → 屏幕自动调至最低亮度 + 暖色滤镜，音量自动降至30%

安抚选项：

- 安抚故事（温柔短故事，3-5分钟）
- 呼吸引导（跟随呼吸动画，吸气-屏息-呼气）
- 白噪音/环境音持续播放（雨声、海浪、心跳声）

**退出逻辑优化（V2.1关键修改）：**
退出安抚模式不再使用简单的按钮（容易被孩子误触导致中断）。改为以下高门槛方式：

- 方式一：同时使用三根手指轻点屏幕，并出现3秒倒计时确认浮层："再抱一小会儿，要离开吗？"
- 方式二：长按屏幕任意位置3秒，屏幕上方月亮精灵低头闭眼，出现进度环，松手即取消。
- 所有退出确认提示均使用最低亮度柔和色调，不造成光刺激。
- 家长端远程退出：若安抚模式由家长端首页"一键安抚"触发，该按钮将变为"结束安抚"，点击后孩子端自动退出安抚模式。

结束后：家长端同步收到安抚记录（次日可查看事件详情）

**睡眠模式详细设计**

| 触发条件       | 行为                              |
| ---------- | ------------------------------- |
| 故事播放完成     | 自动切换为白噪音，音量渐弱至40%               |
| 定时关闭倒计时5分钟 | 屏幕亮度开始渐暗，提示"月亮精灵要休息啦"           |
| 定时关闭触发     | 音量渐弱至0（30秒），屏幕渐暗至熄灭             |
| 孩子触碰屏幕     | 屏幕短暂亮起（最低亮度），显示守护IP睡觉动画，5秒后再次熄暗 |

#### 3.2 家长端核心流程

**数据查看与分享流程**

进入家长端 → 查看周统计卡片（含同龄对比基准）→ 查看趋势图表（入睡时间/夜醒次数/总时长）→ 查看详细数据 → 生成周报/月报 → 分享给家人（微信/家庭群）/ 分享到社交平台（生成分享卡片）

**数据呈现优化**

| 数据指标   | 呈现方式        | 对比基准             |
| ------ | ----------- | ---------------- |
| 平均睡眠时长 | 数字 + 趋势箭头   | 同龄儿童平均值 + 自家上周对比 |
| 入睡时间   | 时间 + 稳定性评分  | 建议入睡时间区间         |
| 夜醒次数   | 次数 + 严重程度标签 | 正常范围参考值          |
| 打卡连续天数 | 天数 + 勋章激励   | 个人最长记录           |

**智能推荐逻辑**

家长首页的知识推荐基于数据驱动：

- 数据显示入睡时间推迟 → 推荐"如何建立稳定睡前仪式"
- 数据显示夜醒频繁 → 推荐"孩子夜醒的常见原因与应对"
- 孩子年龄即将变化 → 推荐"4-5岁儿童睡眠发展特点"

#### 3.3 交互设计原则

| 原则            | 说明                   | 落地要求                |
| ------------- | -------------------- | ------------------- |
| 简洁直观          | 核心操作不超过3步            | 安抚模式≤2步直达；故事播放≤3步   |
| 反馈及时          | 操作后150ms内给予视觉反馈      | 按钮点击态、加载态、成功/失败态全覆盖 |
| 趣味性           | 动画和互动元素吸引孩子          | 勋章动效、IP互动、成长里程碑动画   |
| 安全感           | 柔和色彩和温暖视觉            | 暗色模式、低刺激配色、渐进过渡     |
| 容错性           | 允许误操作并可恢复            | 播放状态保持、进度自动保存、撤销操作  |
| 一致性           | 相同操作相同反馈             | 孩子端/家长端各自保持交互范式统一   |
| 中断柔性（V2.1新增）  | 故事/课程播放时不因页面跳转而强行终止  | 顶部悬浮提示回流            |
| 防误触优先（V2.1新增） | 关键退出操作采用复合手势或长按+确认机制 | 安抚模式三指触摸退出、儿童锁验证    |

### 四、视觉风格定义

#### 4.1 设计主题

> **温暖治愈 · 安全陪伴**

设计理念：

- 基于儿童心理学，营造安全舒适的视觉氛围
- 柔和的色彩搭配，避免刺激
- 圆润的造型，亲和可爱
- 暗色模式作为核心场景（夜间使用）的默认体验

#### 4.2 色彩体系

| 月光蓝深色 | #4A8299 | 家长端强调色、图表高亮                   |  4.8:1 ✓  |
| 奶油白   | #FFF8DC | 孩子端背景色                        |     —     |

**V2.1色彩合规强化：**

- 温暖橙 `#E8967A` 仅允许用于背景装饰、大面积色块、卡片背景。
- 所有功能性文本（按钮文字、链接、图标）必须使用温暖橙深色 `#C4725A`（白底对比度4.6:1，满足WCAG AA标准）。
- 所有文本与背景对比度 ≥ 4.5:1（正文），大字文本 ≥ 3:1。

| 环境光感应 | Expo-Sensors (LightSensor)                    | 暗色模式自动切换决策                    |
| 路由导航  | React Navigation                              | 原生栈导航、Tab导航                   |
| 后端运行时 | Node.js + Fastify (TypeScript)                | 高性能HTTP框架，插件化架构               |
| 数据库   | SQLite(开发) → PostgreSQL(生产) + Prisma ORM      | 类型安全，零配置起步，平滑升级               |
| 对象存储  | 阿里云OSS / AWS S3 + CDN                         | 音频、Lottie文件分发                 |
| 推送服务  | Expo Server SDK / Firebase Admin SDK          | 服务端触发推送                       |
| 部署    | Docker + Nginx + 单服务器                         | 最小运维，0-1阶段最优                  |

#### 8.3 Windows环境开发流程

本方案的核心优势在于**完全支持Windows开发环境**，通过以下流程实现iOS应用的高质量交付：

1. **本地开发：** 在Windows上使用VS Code + Node.js进行编码，通过Android模拟器或Expo Go在真机上进行大部分UI和逻辑调试。
2. **云端构建：** 当需要生成iOS测试包时，使用EAS Build（Expo Application Services）在Expo的macOS云端自动完成Xcode构建和签名，生成`.ipa`文件。
3. **真机测试：** 通过TestFlight分发到iPhone进行最终验证（音频后台、推送、亮度调节等平台特性）。
4. **发布上线：** 使用EAS Submit一键提交App Store Connect。

此流程无需购买Mac硬件，零额外成本，且最终产出为真正的原生App（ARM64二进制），非WebView套壳。

### 九、前端技术方案详述

#### 9.1 框架选择：React Native + Expo

**选择理由：**

- **iOS优先体验：** 搭配react-native-reanimated在UI线程执行动画，保证60fps，Lottie动画直接渲染设计师交付的JSON文件，与原生体验无异。
- **Windows完整支持：** 本地开发环境仅需VS Code + Node.js，可通过Android模拟器或Web预览调试UI逻辑；iOS构建完全交给EAS Build云端Mac环境。
- **最小依赖：** 核心动画、音频、文件存储仅引入5个轻量库，无桥接性能损耗。
- **热更新能力：** Expo Updates支持无需发版的快速修复，紧急Bug可即时推送。
- **未来扩展：** 同套代码可直接构建Android版本，无需二次开发。

**为什么不选Flutter：**
Flutter自绘引擎性能出色，但Lottie支持需依赖`lottie-flutter`插件，功能滞后于原生Lottie SDK；音频后台播放需自行封装平台通道，增加复杂度和依赖。对于0-1阶段，React Native的JavaScript生态在快速迭代和调试上优势显著。

**为什么不选SwiftUI原生：**
SwiftUI虽然能达成最极致的原生体验和最少依赖（仅1个Lottie库），但需要macOS环境进行开发和构建。在当前Windows开发环境的约束下，React Native + Expo云端构建是最务实的选择。

#### 9.2 核心依赖清单（5个核心库）

| 库                       | 用途         | 说明                           |
| ----------------------- | ---------- | ---------------------------- |
| react-native-reanimated | 高性能动画      | UI线程执行呼吸动画、粒子特效、弹性插值，保证60fps |
| lottie-react-native     | Lottie动画播放 | 直接渲染AE导出的JSON，守护IP、勋章庆祝等设计直出 |
| expo-av                 | 音频播放       | 后台播放、进度控制、白噪音无缝切换，定时关闭逻辑     |
| react-native-fs         | 文件缓存       | 故事音频、课程资源离线存储到设备本地           |
| zustand                 | 状态管理       | 1KB体积，管理全局播放状态、暗色主题、安抚模式开关   |

**无需引入的库：**

- Redux/MobX → Zustand替代
- Axios → fetch API
- React-Native-Elements等UI库 → RN内置组件+StyleSheet完全满足
- React-Native-Track-Player → Expo-AV替代
- 额外推送库 → Expo-Notifications内置在Expo SDK中

#### 9.3 关键技术实现

##### 动画实现

- **Lottie动画：** 使用`lottie-react-native`加载设计师交付的JSON文件，通过Reanimated的`useAnimatedProps`控制播放进度、循环次数和速度。
- **呼吸动画：** 呼吸节奏参数按年龄段差异化（3-4岁：2.5s吸-1s屏-3s呼；5-7岁：3s吸-1.5s屏-4s呼），通过Reanimated的`withTiming`和`cubic-bezier`缓动函数控制，同时渲染动态缩放圆环作为视觉提示。
- **勋章庆祝：** Lottie播放一次后自动回弹初始帧，配合1.5秒弹性插值实现弹入效果。
- **粒子特效：** 使用Reanimated创建多个小型动画视图，模拟粒子扩散。

##### 音频播放

- 使用`expo-av`创建`Audio.Sound`实例，配置`playsInBackground: true`实现后台播放。
- **定时关闭：** 通过`setTimeout`结合`setVolumeAsync`逐帧降低音量（30秒内从100%降至0），然后`stopAsync`停止播放。
- **中断恢复：** 监听`Audio.InterruptionModeIOS`，来电/闹钟结束后自动恢复播放。
- **迷你播放器：** 全局状态管理当前播放状态，底部常驻控制栏。

##### 暗色模式与环境光

- 主题切换基于`Appearance` API + 自定义Context，支持"跟随系统""始终暗色""始终亮色"三种模式。
- 使用`expo-sensors`的`LightSensor`获取环境光照度：< 3 lux强制暗色，3-50 lux结合系统时间决策，> 50 lux保持亮色。
- 安抚模式下强制使用`SystemBrightness.setBrightness(0.1)`降至最低亮度。

##### 儿童锁（成人验证）

- 纯前端实现：随机生成1-10的加法题，`Modal`弹窗展示，输入正确后切换至家长端。
- 不依赖生物识别库，保持轻量，后续可扩展支持Face ID / Touch ID。

##### 安抚模式

- **进入：** 全屏暖色遮罩使用`Animated.View`配合800ms渐入动画，同时降低亮度至0.1、音量至30%。
- **退出：** 使用`PanResponder`监听三指手势（3个触点）或长按3秒，触发退出确认浮层。无直接退出按钮，避免儿童误触。

##### 离线缓存

- 使用`react-native-fs`下载音频/课程文件至`DocumentDirectory`。
- 播放时优先读取本地`file://`路径，网络不可用时显示离线提示并播放已缓存内容。
- 课程进度、打卡记录等使用`AsyncStorage`暂存，联网时批量同步至后端。

##### 推送通知

- 使用`expo-notifications`处理推送权限请求和消息展示。
- 服务端通过Expo Push API或Firebase Admin SDK触发定时提醒（睡前提醒、打卡提醒）、周报推送和安抚事件通知。

##### 锁屏小组件

- 需执行`expo prebuild`后在Xcode中添加Widget Extension（通过EAS Build云端预构建完成）。
- 锁屏放置"一键安抚"按钮，点击后通过Deep Link直接触发主App进入安抚模式。

### 十、后端技术方案

#### 10.1 架构选型

- **运行时：** Node.js + Fastify（TypeScript），高性能、低开销、插件化架构。
- **数据库：** SQLite用于开发阶段（零配置、单文件），生产环境切换至PostgreSQL。使用Prisma ORM管理Schema和迁移，类型安全。
- **缓存：** 轻量使用内存缓存（如`node-cache`），后期可扩展Redis。
- **对象存储：** 阿里云OSS或AWS S3存储音频文件、Lottie JSON、勋章图片等静态资源，通过CDN加速分发。上传使用预签名URL减轻服务端压力。
- **文件存储：** 用户头像、分享卡片等使用OSS存储。

#### 10.2 API设计

- 遵循RESTful风格，JSON格式交互。
- 内容获取（故事列表、课程、知识文章）使用GET端点。
- 数据上报（播放记录、打卡、安抚事件）使用POST端点。
- 数据报告接口（需聚合多种统计数据）预留GraphQL扩展点，前期以REST为主保持简洁。

#### 10.3 推送服务

- 优先使用`expo-server-sdk`直接调用Expo Push API，与前端Expo-Notifications无缝配合。
- 如需要更广泛覆盖（非Expo设备或未来Android独立版本），可集成Firebase Admin SDK通过FCM/APNs发送。

#### 10.4 智能推荐与A/B测试

- **智能推荐：** 基于规则的轻量引擎。在数据库维护规则表，根据睡眠数据指标（夜醒次数、入睡时间趋势、年龄变化）匹配推荐知识文章。无机器学习依赖，足够0-1阶段使用。
- **A/B测试：** 用户注册时随机分配实验组标识（`experiment_group`字段），前端根据分组展示不同界面（如付费墙触发时机），服务端统计各组转化率即可。无需第三方SaaS服务。

#### 10.5 部署方案

- **容器化：** 一个Dockerfile基于`node:18-alpine`，镜像体积<150MB。
- **服务器：** 单台2C4G云服务器（如阿里云ECS），使用`docker-compose`运行Node服务 + Nginx反向代理 + SSL证书。
- **数据库：** SQLite文件挂载至宿主机并定期备份；后期迁移至托管PostgreSQL服务。
- **CI/CD：** GitHub Actions执行lint、build、推送镜像，Webhook触发服务器更新。
- **监控：** 使用`pino`日志输出，接入简单日志收集或暂用`pm2`自带监控。

#### 10.6 核心数据表预估

- `User`（家长账户）
- `Child`（孩子档案，与User关联）
- `Story`（故事元数据）
- `PlayRecord`（播放记录，用于数据分析）
- `Subscription`（会员订阅状态）
- `AuthCode`（验证码）
- `Rule`（推荐规则）
- `RelaxationEvent`（安抚事件记录）
