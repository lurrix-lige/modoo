# Dozoo 前端登录状态管理与路由控制分析报告

## 一、概述

Dozoo 是一个面向儿童的心理健康应用，采用 React Native + Zustand 架构。本文档将详细分析其登录状态管理机制和路由控制策略。

## 二、受登录状态控制的前端导航路由

### 2.1 整体路由架构 (`src/navigation/RootNavigator.tsx`)

应用采用层级化路由结构，主要包含以下路由层级：

```
RootStack (根路由)

│   ├── Login (登录页)
│   ├── Register (注册页)
│   └── Guide (引导页)
├── Main (主内容栈 - 需认证)
│   └── 根据 isChildMode 切换:
│       ├── ChildrenStackNavigator (儿童模式)
│       │   ├── ChildrenTabNavigator (底部标签)
│       │   │   ├── ChildrenHome (儿童首页)
│       │   │   ├── Course (课程)
│       │   │   ├── Breathing (呼吸练习)
│       │   │   └── CheckIn (签到)
│       │   ├── StoryPlayer (故事播放器)
│       │   ├── CourseDetail (课程详情)
│       │   └── BreathingPractice (呼吸练习详情)
│       └── ParentStackNavigator (家长模式)
│           ├── UserDashboard (用户仪表盘 - 初始页面)
│           ├── ParentTabNavigator (底部标签)
│           │   ├── ParentHome (家长首页)

│           ├── GrowthRecord (成长记录)
```

### 2.2 路由访问权限规则

| 路由/区域 | 访问权限 | 说明 |
|-----------|---------|------|
| **Home** | 公开 | 无需登录，显示免费内容预览 |
| **Auth** | 公开 | 包含登录/注册功能 |
| **Membership** | 公开 | 可从未登录状态访问，用于引导付费 |
| **Main (Children)** | 需认证 | 儿童模式主内容区 |
| **Main (Parent)** | 需认证 | 家长模式主内容区 |
| **ChildLock** | 需认证 | 用于模式切换验证 |
| **ComfortMode** | 需认证 | 儿童模式功能 |
| **ChildProfile** | 需认证 | 用户必须创建儿童资料才能完整使用 |

## 三、登录状态管理机制

### 3.1 核心状态模型 (`src/types/userStatus.ts`)

系统定义了三种用户状态：

```typescript
type UserStatus = 'guest' | 'authenticated_unpaid' | 'authenticated_paid';

interface UserState {
  status: UserStatus;           // 用户状态
  isAuthenticated: boolean;     // 是否已认证
  isPaid: boolean;              // 是否已付费
  user?: User;                  // 用户信息
  child?: Child;                // 儿童信息
  lastVisitTime?: string;
  visitCount: number;
}
```

### 3.2 状态管理实现 (`src/store/index.ts`)

使用 **Zustand** 进行状态管理，核心状态包括：

- **isAuthenticated**: 认证状态
- **user**: 用户信息
- **child**: 儿童资料
- **userState**: 完整用户状态对象
- **isChildMode**: 当前是否处于儿童模式
- **isComfortMode**: 是否处于安慰模式
- **themeMode**: 主题模式

核心 Actions：
```typescript
setAuthenticated(isAuth, user)  // 设置认证状态
setPaidStatus(isPaid)            // 设置付费状态
setChild(child)                  // 设置儿童资料
logout()                         // 登出
switchToChildMode()              // 切换到儿童模式
switchToParentMode()             // 切换到家长模式
```

### 3.3 认证服务实现 (`src/services/AuthService.ts`)

**单例服务类**，提供完整的认证功能：

#### 核心功能：
1. **Token 管理**
   - 存储 Access Token、Refresh Token
   - Token 过期时间管理
   - 自动刷新 Token

2. **会话管理**
   - 会话超时检测（默认 30 分钟）
   - 活动记录追踪
   - 超时回调处理

3. **登录方式**
   - 手机号 + 验证码登录
   - Apple 登录
   - 微信登录（占位实现）

4. **付费状态**
   - 付费状态本地存储
   - 远程状态同步

#### 存储键定义：
```typescript
AUTH_STORAGE_KEYS = {
  ACCESS_TOKEN: '@dozoo_access_token',
  REFRESH_TOKEN: '@dozoo_refresh_token',
  TOKEN_EXPIRES_AT: '@dozoo_token_expires_at',
  LAST_ACTIVITY_AT: '@dozoo_last_activity_at',
  IS_PAID: '@dozoo_is_paid',
}
```

### 3.4 应用初始化流程 (`App.tsx`)

```
应用启动
  ↓
初始化 AuthService
  ↓
检查本地 Token 和用户数据
  ↓
如果已认证 → 恢复登录状态 + 同步付费状态
  ↓
注册会话超时回调
  ↓
启动健康检查服务
  ↓
监听应用状态变化（记录活动时间）
```

## 四、路由控制策略

### 4.1 未登录用户的路由访问限制

**当前限制机制**：
1. **欢迎页**（Home）：完全公开，展示免费内容预览
2. **会员页**（Membership）：可从未登录状态直接访问，引导用户注册/登录/付费
3. **主内容区**（Main）：需要登录才能访问，但**没有路由级别的强制拦截**

**注意**：系统**没有实现路由守卫**机制，未登录用户可以通过编程方式导航到 Main 路由，但会因 API 请求失败而无法正常使用功能。

### 4.2 已登录用户的路由访问控制

**初始化主路由选择** (`src/screens/parent/UserDashboardScreen.tsx`)：
- 已登录用户默认进入 **UserDashboard**（家长仪表盘）
- 可以从仪表盘切换到 ParentTab 或儿童模式

**模式切换控制**：
- 通过 `isChildMode` 状态在 ChildrenStackNavigator 和 ParentStackNavigator 之间切换
- 模式切换使用 Zustand store：`switchToChildMode()` / `switchToParentMode()`

### 4.3 不同角色用户的路由访问差异化处理

系统区分**儿童模式**和**家长模式**，但**没有基于角色的权限控制**：
- 两种模式主要是 UI 和功能展示的差异
- 所有已登录用户都可以在两种模式间自由切换
- 没有对特定路由进行角色级别的访问限制

### 4.4 登录后导航策略 (`src/services/LoginNavigationStrategy.ts`)

采用**策略模式**处理登录成功后的导航：

```typescript
// 三种策略
CheckInNavigationStrategy     // 从签到页跳转时
MembershipNavigationStrategy  // 从会员页跳转时
DefaultNavigationStrategy     // 默认情况

// 决策逻辑
从 CheckIn 来 → 检查是否有儿童资料 → 有则返回，无则创建
从 Membership 来 → 检查是否有儿童资料 → 有则进入会员页，无则创建
其他情况 → 检查是否有儿童资料 → 有则返回，无则创建
```

## 六、数据验证与防错机制

### 6.1 儿童资料必填验证
- 登录成功后必须创建或同步儿童资料
- 多个功能依赖儿童数据才能正常工作

### 6.2 会话超时处理
- 30 分钟无活动自动登出
- 会话超时时调用 `errorHandler.navigateToAuthWithReset()` 重置导航

### 6.3 Token 自动刷新
- Token 即将过期（提前 5 分钟）时自动刷新
- 刷新失败时触发会话超时

## 七、存在的问题与建议

### 7.1 已识别问题

1. **缺少路由守卫**：未登录用户可以导航到需要认证的页面，只能通过 API 失败被动感知
2. **无访问权限矩阵**：没有根据用户状态（guest/unpaid/paid）进行精细化的内容控制
3. **儿童模式安全性**：儿童锁只是 UI 切换，无强验证机制
4. **错误处理**：会话超时的导航重置逻辑未完全展示

### 7.2 改进建议

1. **实现路由守卫**：在 RootNavigator 增加认证检查，未登录时拦截到 Home 或 Auth
2. **建立权限矩阵**：根据 UserStatus 控制内容可见性和功能可用性
3. **增强儿童锁**：添加密码/指纹验证等安全机制
4. **完善付费内容控制**：对 VIP 内容实现更严格的访问控制

## 八、总结

Dozoo 前端系统的登录状态管理采用了合理的架构：
- 使用 **Zustand** 进行轻量级状态管理
- 采用 **策略模式** 处理登录后导航
- **AuthService** 单例管理认证全生命周期
- 通过 **isChildMode** 切换不同内容区域

系统在安全性方面有基本的会话管理和 Token 处理，但在路由级别的权限控制方面还有改进空间。
