# 取消登录状态检查的临时方案

## 概述
用于功能迭代阶段临时取消各页面的登录状态检查，以最小代码改动实现。

---

## 方案一：修改 AuthService 认证判断（简单直接）

### 修改位置
`src/services/AuthService.ts`

### 修改方法
让 `isAuthenticated()` 方法始终返回 `true`，绕过所有 Token 和会话检查：

```typescript
isAuthenticated(): boolean {
  return true; // 直接返回 true，跳过所有检查
}
```

---

## 方案二：修改应用初始化逻辑（推荐）

### 修改位置
`App.tsx`

### 修改方法
在 `initializeApp()` 函数中，强制设置为已认证状态：

```typescript
const initializeApp = async () => {
  try {
    authService.setCallbacks(handleSessionTimeout, handleTokenRefreshed);
    // 临时：强制设置为已认证
    const isAuth = true; // 硬编码为 true
    if (isAuth) {
      // 创建一个临时的 mock 用户对象
      const mockUser = { 
        id: 'temp', 
        phone: 'temp', 
        nickname: '临时用户', 
        createdAt: new Date().toISOString() 
      };
      useAppStore.getState().setAuthenticated(true, mockUser);
    }
  } catch (error) {
    console.error('Failed to initialize auth:', error);
  }
};
```

### 推荐理由
1. 只修改一处文件
2. 保持完整的状态管理结构
3. 后续恢复登录检查时只需恢复这一处代码
4. 不影响 AuthService 的其他功能

---

## 方案三：跳过 API 请求鉴权（可选）

### 适用场景
如果后端 API 仍然需要 Token 验证。

### 修改位置
API 请求相关的服务文件（如 `ApiService.ts`）

### 修改方法
在请求头处理中添加临时逻辑：

```typescript
headers: {
  // 注释掉 Authorization 头，或添加临时 mock Token
}
```

---

## 恢复登录状态检查的方法

1. **恢复方案一**：将 `isAuthenticated()` 方法恢复原有逻辑
2. **恢复方案二**：移除硬编码的 `isAuth = true` 和 mock 用户创建逻辑
3. **恢复方案三**：恢复 API 请求头的正常处理

---

## 注意事项

⚠️ **此为临时方案，仅限开发/功能迭代阶段使用**
- 不要提交到生产分支
- 功能验证完成后及时恢复
- 记录改动位置以便恢复
